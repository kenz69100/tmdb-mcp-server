# 0.1.3 — 2026-09-20

## Changed

- **HTTP session posture resolves stateless on every run path** (#3) — `src/index.ts` declares `sessionMode: 'stateless'` in `createApp()`, so a `bunx`, `npm start`, or from-source HTTP server matches the container's default instead of falling through to the framework's `auto` (which resolves to `stateful`) when `MCP_SESSION_MODE` is unset. `.env.example` states the value explicitly. Unblocked by `cyanheads/mcp-ts-core#376` (0.13.1).
- **Claude Desktop and Codex plugin manifests deliver `TMDB_API_KEY` correctly** — `.claude-plugin/plugin.json` sources it from a declared `userConfig` field (`${user_config.tmdb_api_key}`) in place of a raw `${TMDB_API_KEY}` passthrough that never resolved; `.codex-plugin/mcp.json` forwards it via `env_vars`.
- **Every `*_not_found` error-contract entry marks `thrownBy: 'service'`** across the movie/show/season/person/watch-providers tools and the three resources — the TMDB client maps the 404 and throws, so no handler carries a literal `ctx.fail` for those reasons.
- **README restructured** around one Overview section and a per-tool/resource Capability reference, replacing scattered subsections.
- **Framework skill tree moved `skills/` → `framework-skills/`** (mcp-ts-core 0.13.0) — a server shipping a plugin manifest no longer hands its development skills to every installing agent.
- **Community health files scaffolded** — `.github/CODE_OF_CONDUCT.md`, `.github/CONTRIBUTING.md`, and `.github/workflows/codeql.yml` (the repo's one CI workflow, gated on the repo's CodeQL default setup staying off); issue forms gain a server-vs-framework routing note and a security-advisory contact link.
